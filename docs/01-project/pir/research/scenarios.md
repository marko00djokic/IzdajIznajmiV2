# Спецификација dataset-а и сценарија

## Замрзавање dataset-а

Циљ је 24–36 огласа из Београда, Ниша и Новог Сада и 12–18 кандидата после
тврдих филтера по сценарију.
Верзија 0.1 не садржи попуњен dataset. Seed подаци су синтетички развојни
подаци и не смеју се означити као тржишни подаци.

**Табела 1. Обавезна schema (извор: аутор).**

| Поље | Тип/правило |
|---|---|
| `dataset_version`, `listing_code` | непроменљиви идентификатори |
| `price_monthly_eur` | број; валута и период експлицитни |
| `city`, `zone`, `lat`, `lng` | локација; координате се могу заокружити |
| `rooms`, `area_m2` | број; missing вредност је `NA`, не нула |
| `facilities` | канонизована листа, нпр. `Wifi`, `Garage` |
| `rating`, `ratings_count` | оба `NA` ако се критеријум не користи |
| `published_at` | ISO датум или `NA` |
| `source`, `collected_at`, `data_status` | порекло и `synthetic`/`permitted-real` |
| `image_license`, `image_source` | дозвола или `none` |
| `missing_fields`, `notes` | експлицитан траг квалитета |

Фајл се замрзава SHA-256 checksum-ом. Дозвољени реални подаци морају имати
доказ дозволе, без личних података издаваоца и без неовлашћених слика. Забрањен
је scraping комерцијалних сајтова без дозволе.

## Сценарији

**S1 — запослена особа.** Цена и локација су најважније; гаража је пожељна,
али није тврди услов. Конкретан град у оквиру Београда, Ниша или Новог Сада,
зоне и буџет одређују се тек из расподеле
замрзнутог dataset-а тако да остане 12–18 кандидата. Пилот потврђује тежину.

**S2 — студентски/дељени најам.** Интернет је обавезан. Површина,
опремљеност и цена су супротстављени меки критеријуми. Град и буџет се на исти
начин изводе из dataset-а и потврђују пилотом.

За оба сценарија морају постојати Pareto компромиси: ниједан кандидат не сме
бити најбољи по свим критеријумима. Пре експеримента закључавају се текст,
hard filters, критеријуми, дозвољене missing вредности и tie-break правило.

## Независна relevance оцена

Два независна оцењивача, слепа за алгоритам и његов редослед, сваком пару
`scenario × listing_code` додељују `0` (крши hard filter/неупотребљив), `1`
(велики недостатак), `2` (разуман компромис) или `3` (веома добро испуњава
приоритете без критичног недостатка). Оцене се заснивају само на
закључаном сценарију и rubric-у. Неслагање од једног степена решава се медијаном;
веће неслагање документованом дискусијом, а ако нема сагласности трећим
оцењивачем. Чувају се обе почетне оцене, исход и образложење. Празан образац:

| scenario | listing_code | rater_1 | rater_2 | disagreement | adjudicated | note |
|---|---|---:|---:|---:|---:|---|
| | | | | | | |

Овај oracle није формула новог алгоритма. Тек над adjudicated оценама рачунају
се `nDCG@5`, `Precision@3` (релевантност `≥2`, именилац три) и top-1 relevance.
