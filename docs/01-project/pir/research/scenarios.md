# Спецификација dataset-а и сценарија

## Замрзавање dataset-а

У верзији 0.1 циљ је био 24–36 огласа из Београда, Ниша и Новог Сада и 12–18
кандидата после тврдих филтера. Техничка допуна од 23. септембра 2026. садржи
замрзнуте [`dataset-v1.json`](dataset-v1.json) са 30 синтетичких огласа,
[`scenarios-v1.json`](scenarios-v1.json) и
[`manifest-v1.json`](manifest-v1.json) са SHA-256 вредностима. То нису
тржишни подаци. Ручни излаз даје 16 кандидата за S1 и 13 за S2;
[лог](offline-evaluation-log-2026-09-23.md) раздваја доказано од непровереног.
Цена је месечна, али dataset нема посебно поље за минимално трајање најма;
зато избор искључиво дугорочних огласа није проверљив из самог улаза. То треба
разрешити пре финалне емпиријске интерпретације.

**Табела 1. Обавезна schema (извор: аутор).**

| Поље | Тип/правило |
|---|---|
| `dataset_version`, `listing_code` | непроменљиви идентификатори |
| `price_monthly_eur` | број; валута и период експлицитни |
| `city`, `zone`, `lat`, `lng` | локација; координате се могу заокружити |
| `rooms`, `area_m2` | број; missing вредност је `NA`, не нула |
| `facilities` | канонизована листа, нпр. `Wifi`, `Garage` |
| `rating`, `ratings_count` | оба `NA` ако се критеријум не користи |
| `published_at` | ISO датум или `NA` |
| `source`, `collected_at`, `data_status` | порекло и `synthetic`/`permitted-real` |
| `image_license`, `image_source` | дозвола или `none` |
| `missing_fields`, `notes` | експлицитан траг квалитета |

Фајл се замрзава SHA-256 checksum-ом. Дозвољени реални подаци морају имати
доказ дозволе, без личних података издаваоца и без неовлашћених слика. Забрањен
је scraping комерцијалних сајтова без дозволе.

## Сценарији

**S1 — запослена особа.** Цена и локација су најважније; гаража је пожељна,
али није тврди услов. Замрзнути услови су Београд, активан статус и највише
800 EUR месечно; зона и тежине су у `scenarios-v1.json`. Пилот тек треба да
потврди разумљивост и тежину задатка.

**S2 — студентски/дељени најам.** `Wifi` је обавезан. Замрзнути услови су
Београд, активан статус и највише 850 EUR месечно; површина, опремљеност и
цена су меки критеријуми. Пилот тек треба да потврди разумљивост и тежину.

За оба сценарија морају постојати Pareto компромиси: ниједан кандидат не сме
бити најбољи по свим критеријумима. `PirOfflineEvaluatorTest` од 23. октобра
2026. проверава овај услов и постојање пара са супротстављеним предностима;
`PirOfflineEvaluator` одбија измењен улаз без Pareto компромиса.
Hard filters, критеријуми, тежине, нормализација, `as_of` и
`λ=0,25` су уписани у замрзнути JSON; текст задатака и пилот протокол нису
закључани. Измена JSON бајтова тражи нову верзију и manifest checksum.

## Независна relevance оцена

Два независна оцењивача, слепа за алгоритам и његов редослед, сваком пару
`scenario × listing_code` додељују `0` (крши hard filter/неупотребљив), `1`
(велики недостатак), `2` (разуман компромис) или `3` (веома добро испуњава
приоритете без критичног недостатка). Оцене се заснивају само на
закључаном сценарију и rubric-у. Свако неслагање, укључујући разлику од једног
степена, решава се документованом дискусијом до консензуса. Ако нема консензуса,
трећи оцењивач, такође слеп за алгоритам и редослед, даје независну оцену;
коначна оцена је медијана три целобројне оцене. Чувају се све почетне оцене,
исход и образложење. Ово правило је закључано 23. септембра 2026, пре
прикупљања оцена. Празан образац:

| scenario | listing_code | rater_1 | rater_2 | consensus | rater_3 | adjudicated | note |
|---|---|---:|---:|---:|---:|---:|---|
| | | | | | | | |

Овај oracle није формула новог алгоритма. Тек над adjudicated оценама рачунају
се `nDCG@5`, `Precision@3` (релевантност `≥2`, именилац три) и top-1 relevance.
